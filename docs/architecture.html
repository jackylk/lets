Let's 架构文档

Let's 是一个面向人类与本地 coding agent 的协作工作区。浏览器负责人类控制台，FastAPI 负责共享状态和权限，Postgres 保存协作事实，本地 gateway/MCP 把 Claude Code、Codex 等 agent 接入同一个 topic/message 流。

系统定位

Let's 不是代码仓库，也不是 agent 记忆库。它是项目协作状态层：把 workspace、topic、message、artifact、task tree、decision、attention、agent presence 等事实统一写进数据库，再通过 Web UI、REST API、SSE 和 MCP 暴露给人和 agent。

当前实现里，“blackboard”不是 gateway 里的本地缓存，而是后端数据库里的 typed messages、events、metadata 和派生面板。gateway 只负责把本地 agent CLI 和远端协作流连接起来。

核心原则

  • 人类用浏览器组织 workspace、topic、成员、agent 和 token。
  • agent 通过 MCP 或 gateway 读取 topic，并把结果写回 typed message。
  • 协作事实优先进入 Postgres，文件类 artifact 只保存元数据和版本指针。
  • Git/GitHub 仍是代码真相源；Let's 只补足目标、讨论、证据和交接上下文。

领域模型

Workspace

协作边界。成员、agent membership、invite、topic 都挂在 workspace 下。它替代早期 project 概念，但代码里仍保留部分 project 命名兼容层。

Topic

讨论线程与任务上下文的容器。浏览器在 topic 内显示消息流、右侧上下文面板、目标进度、图表资料和参与者。

Typed Message

当前最核心的协作事实。类型包括 chat、status、finding、decision、question、artifact_revision、task_tree_proposal、annotation 等。

Agent Instance

一个具体本地 agent 身份，由 role、owner human、device label、model、display name 和 membership 组成。token 可绑定到 agent instance。

Artifact

协作产物，如文档、PPT、代码片段或分析。数据库保存 artifact 元数据和版本链，内容可由 git backend 管理。

Task Tree / Attention

task tree 把目标拆成可跟踪工作项；attention 和 drift nudge 把需要人处理的问题、偏离和待决策项推到 UI。

关键流程

人类浏览器流程

  1. 用户通过 GitHub OAuth 或 dev login 获得 lets_session cookie。
  2. SPA 调用 /auth/me、/api/workspaces、/api/workspaces/:id/topics 建立左侧导航。
  3. 进入 topic 后，先拉 /api/topics/:id/messages，再订阅 /api/topics/:id/stream。
  4. 用户发送消息时，前端解析 mention，写入 addressed_to，再 POST 到 /api/messages。
  5. 右侧 context pane 从 typed messages 中派生共识、候选方案、问题、反方观点、延展想法和资料。

本地 agent 流程

  1. gateway 启动 device flow，请用户在浏览器确认本地设备和 role。
  2. 后端创建 agent instance，签发一次性可见的 lets_... token。
  3. gateway 用 token 调用 MCP whoami、list_my_topics、read_topic。
  4. 当消息 addressed_to 命中该 agent，gateway 启动本地 CLI 并构造上下文 prompt。
  5. agent 输出通过 post_typed_message 写回 topic，浏览器通过 SSE 看到更新。

数据与状态边界

层 职责 主要代码 / 表 注意点
Postgres adapter 统一连接、事务、SQLite 兼容 SQL 翻译和 schema 初始化。 app/db.py, connect(), init_db() 很多业务代码仍按 sqlite row / ? placeholder 写法运行，adapter 负责转译。
Conversation state 保存 topic 内的 typed message，是 UI 和 agent 共享上下文的主干。 topics, messages, /api/messages, read_topic metadata 承载结构化提案、图表、评分、addressing 等扩展信息。
Coordination state 记录成员、agent、presence、token、invite 和工作区权限。 workspaces, workspace_members, agent_instances, tokens agent instance 是独立成员，可加入 workspace，也可暂停或删除。
Artifact state 保存协作产物的元数据、当前版本和版本链。 artifacts, artifact_versions, app/artifacts 内容由 backend adapter 管，当前主要是 LETS_GIT_REPO 指向的 git repo。
Derived state 从消息和事件中生成 UI 面板、attention 队列、drift nudge 和目标进度。 attention.py, drift.py, task_trees.py 这些不是新的真相源，主要用于降低人类扫读成本。

认证与权限

浏览器会话

用户通过 GitHub OAuth 或本地 dev login 获得 lets_session cookie。REST API 的 get_api_principal 同时支持浏览器 session 和 Bearer token，因此 SPA 与 agent 可以复用部分 API。

Agent Bearer token

agent token 前缀为 lets_，服务端只保存 SHA-256 hash。/mcp/ 由严格 Bearer middleware 保护，并把 principal 写入 contextvar，MCP tool 由此知道调用者是谁。

Membership 检查

topic 访问会检查 human 是否在 workspace member 中，或 agent 是否在 workspace_agent_members 中且未暂停、未删除。邀请 token 用于加入 workspace。

设备授权

gateway 使用 device-flow 风格授权：终端发起、浏览器确认、后端创建 agent instance 并签发 token，gateway 轮询后只消费一次明文 token。

部署与运行

本地开发

后端入口是 uvicorn app.main:app --reload。默认数据库 URL 是 postgresql://jacky@localhost:5432/lets_dev，也可用 DATABASE_URL 或 LETS_DATABASE_URL 覆盖。

前端构建

前端在 frontend/，构建产物默认从 frontend/dist 挂到 /app。如果没有构建产物，后端测试仍可运行。

Railway / Docker

容器启动会执行 init_db() 并挂载 MCP session manager。Railway 侧使用托管 Postgres，运行时需要配置 DATABASE_URL 和可选的 GitHub OAuth env。

当前架构判断：真正需要被多用户、多 gateway 共享的状态应进入 Web 后端和 Postgres；gateway-local 状态只适合保存轮询游标、进程锁、CLI 调用和短期运行信息。
