Shared State Coordination

多人 + 多 coding agent 协作台架构

这是一个给多人、多设备、多 coding agent 共同研发项目使用的协作台。 它让人能发布目标和想法、看清各条架构路线和实验结果，也让不同笔记本上的 agent 知道彼此在做什么，尽量复用成果后再继续探索。

四个事实面

GitHub
代码、PR、review、merge、CI
DBay
共享状态、分支记忆、事件、反馈
Web 协作台
黑板、架构图、指标、决策
本地客户端
MCP、daemon、git、runner 采集
场景部分

1. 它解决什么问题

先看用户价值，再看技术实现。

你能同时驾驭多个 agent

不用逐个问 Claude Code 和 Codex 在做什么；你能一眼看到它们各自目标、分支、状态、实验结果和需要你决策的地方。

你和同事能共同研究同一个项目

每个人仍用自己笔记本上的 agent，但大家共享同一份目标、路线、结论和进展，不会各自埋头重复做同一件事。

新想法能快速进入研发流

看到文章、论文、博客后，你把 URL 和想法丢到黑板，agent 领取研究，过一会儿你回来直接看结论和下一步建议。

架构探索不再只藏在 markdown 里

track、initiative、hypothesis 和它们之间的关系以图形化方式展示，人能看懂当前在探索哪几条路线。

agent 尽量复用彼此成果

后来的 agent 会先查已有 branch、finding、artifact、benchmark，不再重复读同一篇论文或重做同一个 spike。

结论以证据驱动

LoCoMo、PersonaMem、测试、CI 都绑定到具体 branch 和 commit，路线是否继续不靠口头印象，而看指标。

2. 人与 agent 如何协同

从一个新 idea 到正式研发路线。

A
黑板是新想法入口不是所有输入都先变成任务；先成为 Idea，再由 agent 研究。
B
人保留决策权agent 可以建议 promote，但是否升格为正式路线由人确认。

3. Agent 与 agent 如何协同

避免重复探索，尽量复用彼此成果。

A
先查共享状态，再开工每个 agent 启动时先查 active initiative、peer findings、branch ownership。
B
复用优先于重复如果别人已有 finding、artifact、metric 或半成品，后来的 agent 应优先接力。

4. 一个完整协作周期

从外部文章到最终合并代码，所有参与者都在同一个状态图里。

技术部分

5. 总体架构

协作台不是替代 GitHub，而是在 GitHub 之上补上共享状态和人机协同层。

核心边界：GitHub 是代码主权，DBay 是协作主权，Web 协作台是人的控制面，Local Client 是 agent 的接入面。

6. 本地客户端

每台笔记本都装，所有 agent 用同一套 MCP 协议接入。

组件职责
MCP Server给 Claude Code、Codex、其他 agent 提供统一工具：领 idea、查 peer work、报状态、发 finding。
Local Daemon维护 session、heartbeat、离线缓存、设备身份、agent 身份。
Git Scanner采集 worktree、branch、commit、PR 绑定关系。
Runner Scanner采集 benchmark、test、eval 结果并绑定 commit/config。
CLI给人和脚本用：join、status、sync、doctor。

7. 新同事 / 新 agent 接入

重点是让加入成本足够低。

1
安装 Local Client登录组织账号，绑定 GitHub 身份和设备。
2
安装 MCP 配置Claude Code、Codex 或其他 agent 都只认同一组协作工具。
3
加入项目自动 hydrate roadmap、active initiative、open ideas、当前反馈。
4
开始协作先查共享状态，再领取 idea/task，再在 GitHub 上推进代码。

8. 我对系统边界的最终定义

如果这四句话你认可，我们的架构就基本对齐了。

GitHub = 代码真相

最终代码怎么合、谁 review、CI 是否通过，全部以 GitHub 为准。

DBay = 协作真相

共享状态、idea、initiative、agent WIP、finding、反馈、事件和 branch-local context 由 DBay 承担。

协作台 = 人类控制面

人看目标、看路线、看证据、给反馈、做决策，不需要钻进每个 agent 的上下文里。

Local Client = 边缘接入层

把每台笔记本上的 agent、git、runner、runtime 接入共享系统，支持新同事快速加入。

以 hypothesis 为中心

task 只是执行单元，真正要管理的是路线、假设、证据和决策。

目标是 shared state，不只是 memory

这个系统要催熟的是多 agent、多设备、并发读写下的状态协同架构。
